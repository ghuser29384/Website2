# MPGF Formal Mechanism Raw Source

Status: verbatim complete for the implemented exact-pilot proportional allocation profile.

The implemented MPGF pilot mechanism for the current production deployment is a non-real-money exact-pilot profile. Participants may view candidate moral public goods, record non-real-money pledge rehearsal state, draft pool reasoning, simulate ballots, and submit manual external-payment evidence for review. Manual evidence review can inform contribution state only after reviewer approval; automated payouts and real-money allocation effects are outside this active profile.

The active allocation domain is the May 2026 MPGF pilot cycle with at most four approved ordinary-pool alternatives, at most four ballot records, integer cents, integer basis-point ballot weights, and exact rational verifier arithmetic. Approved alternatives are sorted by stable alternative id. Ballot weights are clamped to the inclusive range from 0 to 10000 basis points. Strong-negative weights do not contribute to the ordinary positive score.

The active exact allocation algorithm is `exact_integer_proportional_v0`. For each approved alternative, the solver computes the aggregate positive score in integer basis points. If budget, approved alternatives, or total positive score are zero, all budget carries over. Otherwise, each alternative first receives `floor(budget_cents * score_bps / total_score_bps)`. Remaining cents are distributed by descending remainder numerator, with ascending `alternative_id` as the deterministic tie-break. The resulting allocation plus carryover must equal the locked budget exactly.

The active certificate schema is `mpgf-solver-certificate-v0.3`. A valid certificate records the canonical instance hash, budget cents, candidate allocation, candidate objective value, feasibility proof, region-enumeration proof, deterministic tie-break proof, and zero optimality gap. The independent verifier recomputes the canonical instance hash, budget equality, integer non-negative allocation cents, objective value, caps, risk exposure, tail-loss condition, and zero optimality gap before live ordinary allocation is allowed.

The active support profile is `mpgf-solver-support-exact-pilot-v1`. It supports no more than four alternatives, four ballots, two canonical breakpoints per ballot, four region-enumeration regions, zero branch-and-bound nodes, 32768 certificate JSON bytes, and 1000 ms verifier runtime. If an instance exceeds those active limits, requires inactive branch-and-bound, violates feasibility, exceeds certificate size, exceeds verifier runtime, or requests heuristic live allocation, the solver fails closed.

The public production profile is evaluated at `https://www.moraltrade.org`. Public route verification covers `/mpgf`, `/mpgf/contribute`, and `/mpgf/pools`. Participant and admin mutations must remain gated by authenticated repository sessions. Real-money payment provider operations, automated payouts, external payout recording, tax receipts, and production enablement remain governed by their separate legal, compliance, payment, privacy, receipt, retention, launch, deployment, and approval gates.
